# Yaran web UI/UX audit against T3 Code

Date: 2026-11-04. Yaran base `2d8a9a5b`; T3 Code reference checkout `21318f1ab`.

## Result and scope

**9.5/10 on the internal rubric below.** Three audit/fix rounds and a separate adversarial review found and closed the material defects listed here. This is an engineering assessment of the tested web interface, not a usability-study result, an accessibility certification, or a claim of pixel parity with T3 Code.

Scope covers the desktop workspace, narrow-screen hub and panes, agent/project creation, search and navigation, menus, provider/file tabs, editor and diff review, settings, macros, environment/startup editors, destructive confirmations, and reconnect/error states. The separate terminal UI and marketing site were not rescored. Shared welcome copy, working-cue calibration, documentation, and the screenshot fixtures were updated where the web audit exposed a direct contradiction.

T3 Code supplied the reference patterns: action-oriented empty states, readable hierarchy, searchable settings, named current navigation, independent action hit areas, keyboard-complete menus/tabs, and recovery that retains drafts. Its authenticated live workspace was unavailable in the preview profile because it required pairing. The comparison used its local UI source, including `NoProjectsHero`, `SidebarChrome`, `SidebarThreadRow`, `SettingsSidebarNav`, `workspaceFocus`, and the Base UI menu primitives. Yaran retains its terminal-based provider interface and existing dark token system.

No numerical pre-change score was recorded. The first pass reproduced several workflow and accessibility blockers, so a pre-change 9.5 would not have been defensible.

## Fixed rubric

Weights were set before the browser re-audit. A 10 means the tested workflows are complete with no material defects; 9 means complete with minor friction; 8 means repeated discovery or recovery friction; 7 or less means a workflow is blocked. Passing 9.5 requires no known blocking defects, every category at least 9, and desktop, phone, short-viewport, empty, and failure-state evidence.

## Findings closed

| Finding | Fix and regression evidence |
| --- | --- |
| Form controls depended on disappearing placeholders or unassociated labels. | Added accessible names and label associations across creation, rename, provider, commit, settings, macros, and environment/startup forms. Added associated inline error descriptions. |
| Confirming CJK composition could create/rename/commit or dismiss a dialog. | Enter handlers and shared dialog Escape handling respect composition and the legacy 229 fallback. Regression cases exercise the original premature submissions. |
| Global environment and macro saves discarded drafts before a request succeeded. | Store writes return a success result. Editors await success, keep failed drafts, and block duplicate writes. Macro reorder and Save cannot overlap. |
| Slow project/environment/startup saves could close a newly reopened or different target. | Pending dismissal guards, target-keyed forms, and mounted-form checks prevent stale completion from discarding a new draft. Six lifecycle checks cover pending Cancel/Escape and target changes. |
| Malformed environment lines were silently omitted by whole-map replacement. | One shared validator reports the offending line and blocks saving in all three editors. Comments, empty lines, and values containing `=` remain supported. |
| Failed project-folder inspection was hidden and still allowed Add project. | Show the inspection error, block submission, and keep the folder-selection retry available. |
| Settings rows painted through the footer instead of scrolling. | The shared ScrollArea uses a bounded grid track and a shrinkable viewport. Browser measurements verify content scrolls inside the viewport while the dialog/footer stay bounded. |
| Numeric settings clamped an intermediate digit before the user could finish typing. | Keep incomplete values local, commit valid numbers, and clamp completed edits on blur. A two-keystroke test and browser input check verify `1` then `6` remains `16`. |
| Settings required scanning a long list. | Descriptor-based search matches labels, descriptions, config keys, and group captions; changing the search preserves edits. Section resets are hidden during filtering so hidden settings are not reset accidentally. |
| Changed-file rows could not open a diff from the keyboard. | Use a named native Open diff button, with selection and action controls as siblings. Browser Enter activation opens the requested diff. |
| Provider/file tabs lacked tablist keyboard behavior and nested their actions inside tab controls. | Use installed Base UI tabs, manual activation, roving arrows/Home/End, and independent menu/Close buttons. Arrows move focus without switching PTYs; Enter activates. |
| A PR link was nested inside an agent-selection button. | Make the native link a sibling with its own touch target and focus outline. Agent/terminal selections expose `aria-current`. |
| Agent search lacked visible keyboard focus and an explicit clear action. | Add a focus-within ring, accessible clear control, Escape clearing, and focus return to the field. |
| An unloaded workspace briefly claimed it had no agents. | Render a separate announced loading state until the workspace arrives. |
| The home center pane offered decoration but no next action. | Reuse the shared welcome action slot and launcher decision for Add project or New agent. |
| The phone app-menu sheet advertised menu roles without menu keyboard behavior. | Add one roving tab stop, wrapping Up/Down, Home/End, first-letter navigation, Right drill, and Left/Back focus restoration to the originating row. |
| The offline alert did not isolate keyboard/screen-reader focus. | Use the installed dialog primitive, focus Reconnect, retain the modal on Escape, restore focus after recovery, and respect reduced motion. The small-screen logo scales to fit. |
| Phone file rows were 28px high. | Use 40px rows for coarse pointers, including the virtualization offsets and total height. Desktop density remains 28px. |
| Choosing a phone file left most of the screen occupied by the explorer. | Tree and search selections collapse the explorer on phones. The header toggle reopens it. Verified on the Pixel with readable full-width code. |
| StrictMode's effect replay could leave the development file tree loading forever. | Reset the mounted flag on setup. A previously failing StrictMode regression now passes; a fresh browser load populates the tree. |
| Viewport configuration limited user zoom. | Remove the scale limit and keep visible touch inputs at least 16px to avoid focus zoom. Hidden xterm/Monaco inputs retain their calibrated cursor/IME geometry. |
| Working-status text became unreadable at the pulse floor. | Raise the shared floor from 0.4 to 0.8. Browser color measurements show the worst selected-row contrast improves from about 2.19:1 to 4.85:1. Shared Rust timing and CSS contrast regression checks pass. |
| New-agent guidance incorrectly promised a branch/worktree in shared mode; other tips named retired control locations. | Correct creation copy, six welcome tips, and the directly affected docs. Keep the screenshot-only preview fixture explicitly in worktree mode so its seed remains valid. |

## Optimization follow-up

The subsequent code pass removed repeated work while retaining the audited interactions and recovery guards:

- Both editor shells now load the editor body on demand. A shared loader announces progress and uses the existing failed-chunk reload recovery.
- File search stops after finding its 300 visible matches. Narrow queries still scan as far as needed, preserving result order and case-insensitive matching.
- Sidebar sorting, filtering, and terminal assembly are reused until their inputs change. Selection remains live. Project membership uses a linear pass instead of a nested lookup, and terminal assembly no longer copies its fresh array before sorting.
- Preferences filters only when its normalized search changes; empty search reuses the descriptor groups.
- Seven closed dialogs skip workspace lookups. Agent environment/startup dialogs also skip project lookup for standalone agents.
- Project environment editors compare own keys and values directly, avoiding redundant writes when only key order or comments differ. Deletions and prototype-named keys remain covered.
- Macro editing reuses its already isolated draft; edits and reordering replace arrays and entries. Environment parsing drops redundant trimming checks.

The pre-optimization source was saved and rebuilt with the same configuration and dependencies. The eager index asset decreased from 921,576 to 845,455 bytes. The three JavaScript assets directly referenced by the entry HTML total 1,035,793 bytes after the change, down from 1,111,914. Their combined gzip size decreased from 338,258 to 316,203 bytes using the same compressor. This measures transferred code size, not browser startup or interaction timing. Opening the editor now requests its additional chunk.

Verification: **286 test files, 4,878 tests passed**, production build passed, full ESLint plus checks of the final test edits passed, and `git diff --check` passed. New checks cover deferred loading and failed-chunk recovery, bounded search, live selection with cached list data, immutable macro edits, and environment no-op detection. Existing editor tests now settle dynamic imports and the held save/check promises explicitly. The font guard checks the bundled font and line height independently of responsive font size. Independent review found no blocking issues.

At the end of that optimization pass, browser/physical-phone flows had not yet been repeated. The verification pass below supersedes that checkpoint. No dependencies were added; the large-chunk advisory remains.

### Coverage limits and cleanup

The physical virtual display never presented a native soft keyboard, so IME resize/occlusion is unverified. iOS Safari, a live screen-reader session, authenticated provider/GitHub success, push, and external-editor launching remain unverified. Some destructive actions against original seed data were inspected and canceled; actual deletion used only fixtures created for this audit. These exclusions mean this is broad route and state coverage, not a literal proof of every platform or backend combination.

The disposable project/agent/worktree and root file fixtures were removed. The phone's test file was committed and removed in its disposable Docker worktree, which is clean; those fixture commits do not touch the source repository. Original seed changes in add-rate-limits were preserved. Macro order and global form values were restored. The fault proxy was stopped, owned browser tabs were closed, and the phone pool has no active lease. The isolated preview remains available with the final embedded build. No source-repository commit or production deployment was made.
