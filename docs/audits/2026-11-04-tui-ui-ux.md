# Yaran TUI UI/UX audit against T3 Code

Date: 2026-11-04. Yaran base `2d8a9a5b`; T3 Code reference checkout `21318f1ab`.

This report covers the terminal UI. The earlier [web audit](2026-11-04-ui-ux.md)
has a separate scope and score.

The later [main-workspace redesign and review](2026-11-04-tui-main-workspace.md)
records the visible interface work that followed this pass.

## Assessment

The tested TUI reaches **9.5/10 on this internal engineering rubric**. The
weighted result is 9.525, reported to one decimal place. This is a judgment of
the workflows and terminal sizes below, not a user-study result or an
accessibility certification. The baseline had reproducible draft-loss,
confirmation-clipping, contrast and focus defects; it was not assigned a
retrospective numeric score.

The main workspace layout, pane chrome and grouped/compact sidebar were
retained. This pass primarily fixed behavior, recovery and readability; it did
not deliver a substantial visual redesign of the main TUI. The score above
should not be read as an overall visual-design rating.

## Comparison with T3 Code

T3 Code was a reference for interaction quality rather than a pixel template.
The comparison used the local source at the revision above: `NoProjectsHero`,
`SidebarChrome`, `SidebarThreadRow`, `SettingsSidebarNav`, and
`lib/workspaceFocus.ts` under `apps/web/src`. Its authenticated workspace was
unavailable in the preview profile because it required pairing, so this is not
a claim of equivalent live, authenticated coverage of both applications.

| T3 Code pattern | Terminal equivalent reviewed in Yaran |
| --- | --- |
| Actionable empty states | Existing add-project/agent routes, standalone route, and an explicit message with the bound clear key for an empty search. |
| Named workspace regions and focus restoration | Tab/Shift-Tab pane movement, active pane borders, provider tabs, and moving focus back to Changes when Staged/Commit disappear. |
| Clear current navigation and secondary hierarchy | Grouped and flat agent lists, selection, activity/attention cues, readable hints and status text. |
| Recoverable settings and explicit outcomes | Configuration drafts survive failed saves; a pending save is visibly pending; only its matching successful completion closes the form. |
| Controls remain available in constrained layouts | Status rows stay outside tall forms; confirmations measure their wrapped content; the process picker fits all four actions at 80 columns. |

Yaran keeps its existing theme engine, shared controls, PTY input model and
keyboard conventions. No new dependency or parallel widget system was added.

## Fixed findings

1. **Configuration drafts disappeared on failed saves.** Global environment
   editing now closes only on success. Project environment and startup-command
   forms wait for the matching persistence result, retain failed drafts and
   allow retry. Pending key/mouse input cannot dismiss or submit the form again.
   A reload refuses a global save without queuing a stale draft. A worker that
   fails to spawn now emits a normal correlated failure completion, releasing
   the pending form.
2. **Tall forms covered the error footer at 80×24.** Configuration and macro
   forms use the existing bounds that reserve both global footer rows. Invalid
   environment-line errors and failed-write messages are readable while the
   draft remains on screen.
3. **Confirmation dialogs clipped identity and consequences.** Delete Terminal,
   Discard, Quit, Kill Running confirmation, Delete Macro, Shared Writer,
   Initial Commit, Init Repo and Use Existing Branch now size from their
   pre-wrapped bodies and fixed button rows. Shared Writer uses the shared name
   chip. The process picker also reserves enough width for its four existing
   action buttons.
4. **File-list focus could remain on an invisible section after commit.** When
   Staged/Commit disappear, focus returns to Changes and obsolete commit editing
   clears. The next discard command acts on the visible selected file.
5. **Long selected paths hid change counts.** Selected and unselected paths share
   the real column budget and Unicode display-width calculation. ASCII and CJK
   paths keep their addition/deletion counts at 80 columns. Selected status and
   counts use the selection foreground; the status character and +/- signs
   preserve their meaning without low-contrast green/red/yellow text on cyan.
   A narrow heading retains its file count and omits the redundant totals when
   the complete summary cannot fit, preventing misleading partial numbers.
6. **Important secondary text was too faint.** The default theme's instructions,
   inactive state, provider label, tips and informational status now pass the
   4.5:1 regression checks. Generic themes derive readable selection/banner
   foregrounds and adjust weak inherited body hues only as far toward black or
   white as needed. Explicit `yaran.*` theme overrides remain authoritative.
7. **Search and help left avoidable ambiguity.** An unmatched agent search names
   the state and its configured clear key. Long help key labels retain a gap
   before their descriptions. Help and first-run copy describe shared checkouts
   and optional worktrees accurately. The theme picker explains preview,
   confirmation and save behavior correctly.
8. **Active terminal ordering ignored quiet foreground programs.** It now uses
   working-or-typing state, so a quiet Vim process sorts as active. Rendering
   sorts terminals once and reuses that order for filtering, totals and mouse
   mapping. Existing file-list windowing and diff caches were retained.

## Runtime and visual coverage

All app runtime checks used disposable Linux Docker containers and disposable
repositories/configuration. The host's Yaran process and personal state were
left untouched. Real tmux keyboard and SGR mouse input drove the TUI; captured
ANSI cells were rasterized with the repository's existing terminal renderer and
inspected as images. The renderer used bundled Yaran Mono because MonoLisa was
unavailable on this host.

Focused baseline checks reproduced the lost-draft/footer and contrast failures
before their fixes. Regression coverage also exercises configuration-write and
SQLite failures, retry, pending mouse/keyboard input, unrelated completion,
worker-spawn failure, Unicode file rows, post-commit focus and short-screen
confirmation content. Older tests that expected an immediate project save now
wait for its actual completion; fixtures that intentionally focus Staged/Commit
now include a staged file. Their behavioral assertions were retained.

A flaky human-board watcher fixture was also corrected: its empty directory is
created before the watcher starts, so a legitimate intermediate empty-directory
snapshot cannot race the expected note event. Its assertion and timeout were
not weakened.

## Coverage limits

The scored compact layout starts at **80 columns × 24 rows**. Smaller terminals,
exceptionally long confirmation bodies, arbitrary user theme overrides and all
host terminal palettes are not certified. Init confirmations need at least 48
columns for both fixed-width buttons. Bundled-theme text regressions cover the
listed semantic pairs; they do not certify every decorative border or syntax
highlight color.

Fake providers validate interaction and rendering, not authenticated model
behavior. Remote GitHub authentication, push/PR operations, every provider CLI,
host clipboard integration and native IME/font behavior were not exercised.
Long bursts of informational statuses can queue; the screenshot fixtures wait
for the intended confirmation instead of mistaking an older one for completion.
No release installation, source commit or deployment was performed.
