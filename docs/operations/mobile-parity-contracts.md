# Mobile parity: frozen phase 0 contracts

Phase 0 of `t3-mobile-parity-implementation-plan.md`. This page fixes the wire names and
types that the later tracks (A Rust, B Android machine-view, C shell, E app manifests, D iOS,
F links) build against. Date: 2026-11-17. Values someone else supplies are written as
`<publisher-domain>`, `<org-control-plane>` and `<machine-host>`.

This page was written as the contract only. The native implementation (tracks B, D, E and the
native half of F) is recorded in `mobile-native-parity-validation.md`; section 7 lists the
original downstream items.

Decisions the parent resolved: D1(a) (a native password sheet, the existing `cli-login`, the
CLI session held natively), D2(b) (G6 has a working producer and consumer), no iOS JS bridge
or injected script.

## 2. MachineView.open

```ts
type OpenOptions = OrgOpenOptions | DirectOpenOptions | RoutedOpenOptions;

// Unchanged from before G1. `kind` may be left out, so existing callers compile and behave the same.
{ kind?: "org"; orgId; machineId; host; route?; share? }
// G1
{ kind: "direct"; host; instance?; route?; share? }
// G2: 1..MAX_ROUTES (4) routes with distinct hosts, in the user's order
{ kind: "routes"; routes: MachineRoute[]; instance; route?; share? }

type MachineRoute =
  | { kind: "org"; orgId; machineId; host }
  | { kind: "direct"; host };
```

- `host` must pass `isPublicHost`: lowercase, two or more labels, an alphabetic TLD, and no
  port, IP literal, userinfo or `xn--` label. This is the same rule as `HostRules.host`.
  `route` passes `isAgentRoute`.
- When native code does not support a form, it rejects with its `invalid_arguments` /
  `invalid_argument` code. The current Android build already rejects `direct` and `routes`
  because their `orgId` is missing, and iOS rejects them with `invalid_argument` for the same
  reason. That is the fail-closed behaviour we want. Until track B/D lands, both natives
  ignore `share` on an org open, and Capacitor rejects the new methods as unimplemented.
- `shareBatch` names the held share to hand over. It is taken only if it is still the share
  native holds, compared and taken in one step: another share held rejects `share_changed`
  (nothing taken, no window), none held rejects `no_share`, and a malformed id rejects
  `invalid_arguments`.
- A direct or routed window closes with `ClosedEvent {reason: "error", code}`, where
  `code` is a `DirectClosedCode`:
  - `instance_changed`: the `instance` given and the instance the machine reports differ.
    The shell offers Remove or Keep. Keep rewrites the stored instance and opens again.
  - `no_route`: no route answered with the expected instance.

  `ClosedReason` is deliberately unchanged, so the shell's exhaustive switch keeps compiling.

- `ClosedEvent` gained two optional, non-secret fields (additive; older listeners ignore them):

  ```ts
  interface ClosedEvent { reason: ClosedReason; code?: string; host?: string; requestedHost?: string }
  ```

  - `host`: the host of the route the window was on when it closed. For `instance_changed`
    it is the host whose machine answered with another instance. It is absent for `no_route`
    (no route was chosen) and when the window never had a valid target.
  - `requestedHost`: the first route's host of the open that made this window (the host of an
    org or direct open, `routes[0].host` of a routed one).
  - The shell attributes a close by matching these against its own records, never by
    "the machine opened last".

### Route rules (G2) that every native must enforce

- The instance id is **public**. Matching instances only group routes the user approved
  explicitly. Instance equality is not identity authentication. It never authorizes a new
  origin and never lets one host's session be used on another host.
- Each route signs in on its own. An org route uses its own `CF_Authorization` from
  `session/<host>`. A direct route uses its own record from `session-direct/<host>`. A token
  never follows a route switch to another origin. A route switch destroys the WebView and
  creates a new one, then injects only the new host's credential as a host-only cookie.
- A route is tried at open, at resume after the sockets parked, and from the offline
  overlay's "Try another route". It is never tried under a live, healthy page.

## 3. Session: direct machines (G1, D1a)

```ts
directStatus({ host }): Promise<DirectStatus>
directSignIn({ host }): Promise<DirectSignInOutcome>
directSignOut({ host }): Promise<DirectSignOutOutcome>
```

`DirectStatus` is `{kind:"yaran", instance: string|null, passwordSet, requiredHere, signedIn,
transportEncrypted}`, or one of the shared failures.

`DirectSignInOutcome` is one of:

- `signed_in {host, instance}`
- `not_required`
- `cancelled`
- `wrong_password {message}`
- `rate_limited {retryAfterSeconds, message}`
- `no_password {message}`
- `server_refused {status, code, message}`
- a shared failure

`DirectSignOutOutcome` is `signed_out {serverEnded}`, `vault_locked`, `secure_storage_failed`
or `refused {reason:"invalid_host"}`.

`secure_storage_failed` (added by the native track, 2026-11-17) is also a `SignInOutcome` and a
`DirectSignInOutcome` kind: the key store or vault failed while the app was **unlocked** (a
StrongBox/TEE provider error, a tampered record, a save that failed). Only a locked vault is
`vault_locked`. Its sentence is `fixtures/messages.json` `sign_in.secure_storage_failed`, action
`try_again`. A direct sign-in that ends this way has already revoked the token on the machine.

### Sign-in ids and conditional sign-out (native round 3)

```ts
// DirectSignInOutcome
{ kind: "signed_in"; host: string; instance: string | null; signInId: string }
// SessionPlugin
directSignOut(options: { host: string; signInId?: string }): Promise<DirectSignOutOutcome>
// DirectSignOutOutcome gains
{ kind: "not_current" }
```

- `signInId` is opaque and non-secret: 128 random bits as 22 base64url characters, minted per
  sign-in, stored in the native record, never derived from the token and never usable as a
  credential. Natives reject a malformed one with their invalid-argument code.
- With `signInId`, `directSignOut` ends only that sign-in. When the host's current record is
  another one (a later sign-in, a record an older build wrote without an id, or none), nothing
  is revoked, deleted or cleared and the answer is `not_current`. The comparison is made again
  after every network await, so a sign-in that lands during the revocation survives.
- Without `signInId` it removes whatever is current (Remove machine), revoking a sign-in that
  lands meanwhile as well, up to a bound. If new sign-ins keep landing past that bound, the
  newest one is kept and the answer is `not_current` here too. For a call without an id,
  `not_current` therefore means the host still has a session: the sign-out is incomplete, and
  the shell keeps the machine (or route) listed and says so.
- A sign-in that replaces an existing record revokes the replaced token on the machine (best
  effort), so a superseded sign-in never stays live with nobody holding its cleanup.
- The shell integrates after its own review: its `signed_in` fixtures gain `signInId`
  (`approval.test.tsx`, `direct.test.tsx`), its sign-out switch handles `not_current`, and a
  cleanup of an abandoned approval passes the id that approval returned.

### Session.routeStatus (G2)

```ts
routeStatus(options: { route: MachineRoute }): Promise<RouteStatus>
type RouteStatus = DirectStatus | { kind: "sign_in_required" };
```

- A direct route answers exactly as `directStatus({host})` (including `org_host`).
- An org route is probed at its exact host, `GET /api/v1/auth/status`, redirects off, with only
  that host's own `CF_Authorization` from a `session/<host>` record whose org is the route's
  `orgId`. No usable session (none, expired, another org's, unreadable) or an Access redirect is
  `sign_in_required`: the shell calls `Session.signIn({orgId, target: {machineHost}})` and
  probes again. A locked vault is `vault_locked`. A malformed route rejects with the platform's
  invalid-argument code.
- A matching `instance` only groups routes the user approved. It is not authentication.

The shared failures are:

- `not_yaran`
- `access_required`: a redirect to Cloudflare Access. The user should add this machine
  through its organization.
- `redirected`: any other redirect
- `offline`
- `tls_error`
- `vault_locked`
- `refused {reason}`, where `reason` is `invalid_host`, `org_host`, `response_too_large` or
  `not_json`

Mapping from the server (`crates/yaran-web/src/auth/routes.rs`):

| `cli-login` answer | Outcome |
|---|---|
| 200 `{token, expires_at:null}` | `signed_in` (the token is kept natively and never returned) |
| 401 `wrong_password` | `wrong_password` |
| 429 `rate_limited` (`retry_after_seconds`) | `rate_limited` |
| 409 `no_password` | `no_password` |
| 409 `password_changed`, 400 `password_too_long` / `bad_request`, 403 blocked, 500 `internal` | `server_refused {status, code: body.error}` |

`message` is the machine's own `message` field. It is untrusted text: native trims it to 300
characters and removes control characters, and the shell renders it as plain text.

### Rules every native must enforce

1. **The password never crosses the bridge.** It is typed into a native sheet
   (`FLAG_SECURE`, a password input type, autofill allowed). The `CharArray` or buffer is
   zeroed after the POST.
2. **Redirects are refused, never followed.** Before the password sheet appears, native runs
   an unauthenticated `GET /api/v1/auth/status` with redirects off. It POSTs `cli-login`
   with redirects off and attaches a stored session to any request only after the answer
   proves it is a yaran. A 3xx is classified as `access_required` (the Location is on
   `*.cloudflareaccess.com`) or `redirected`. The password is not sent and nothing is
   attached.
3. **Credentials are per host.** `directStatus` attaches only the session stored for that
   exact host.
4. **A host cannot be both.** A host that has a `session/<host>` (org) record is refused with
   `org_host`. The shell runs the same guard against its org machine lists.
5. **Cookie.** The session is injected as `yaran_session_<port>=<token>; Path=/; Secure;
   HttpOnly; SameSite=Strict`. It is host-only and has no expiry. The name must match
   `^yaran_session_[0-9]{1,5}$` and the value must match `^[A-Za-z0-9_-]{1,256}$`. Native
   learns the port suffix from track A's additive `cookie_name` field on the `cli-login`
   answer.
6. **Sign-out** sends `POST /api/v1/auth/cli-logout` with the bearer, best effort, with no
   redirects followed, then deletes the record and the host's web data. `serverEnded` says
   whether the machine answered 204.

### Vault namespaces: secret and non-secret are separate

| Namespace | Holds | Who may read it |
|---|---|---|
| `session-direct/<host>`: vault namespace `session-direct`, key `sha256(host)` through `VaultSecrets` | `{token, cookie_name, instance, issued_at}`, in the `locked` class when the app lock is on | **Native only.** |
| `direct` / key `list` (JS `SecureStore`) | Metadata only: `{id, label, host, instance, addedAt, routes}` | The shell. |

The `session-direct` name was chosen because both platforms already reserve the `session`
prefix with a prefix match: Android in `securestore/Validation.kt` (`RESERVED_NAMESPACES`,
`startsWith`) and iOS in `core/.../PluginArguments.swift` (`reservedNamespaces`, `hasPrefix`).
A JS `SecureStore` call that names `session-direct` is therefore already refused with
`reserved_namespace`, and the reserved list does not need to grow.

**Requirements for implementers:**

- Never put a bearer, a password or a cookie value under `direct`, or under any namespace
  that is not reserved.
- Tracks B and D each add a test proving that JS `SecureStore.get`, `set`, `remove` and
  `list` on `session-direct` are refused, on both Android and iOS.
- If a future secret needs a namespace outside the `session`, `handoff`, `install` and
  `push` prefixes, the native allowlist in those two files must be extended first, on both
  platforms, and its tests must cover it.
- `eraseAll` already removes every namespace. `SessionStore.hostsFor`, which lists
  `session/`, does not see `session-direct`, so an org sign-out never touches a direct
  machine.

## 4. Share intake (G5)

```ts
MachineView.shareStatus(): Promise<ShareStatus>        // {kind:"none"} | {kind:"pending", count, batch}
MachineView.discardShare({batch}): Promise<void>       // share_changed if another is held; resolves if none
addListener("shareReceived", (e: ShareReceivedEvent) => …)
// {kind:"files", count, dropped, batch} | {kind:"refused", reason:"no_files"|"unsupported_os"}
MachineView.open({…, shareBatch})                       // share_changed / no_share / invalid_arguments
```

- JS only ever sees a count, a state and an opaque batch id. It never sees a URI, a file
  name, a path or bytes. The batch id is a random UUID minted for each share (on iOS, the
  name of the share's private folder; on Android, in memory), unrelated to the files and to
  any credential: it identifies a share so that a press acts on the share it was made for.
- A press acts on the batch it shows: `open({shareBatch})` and `discardShare({batch})` compare
  and act in one native step, so a share that arrives between a press and the native command
  is never taken or discarded in its place (`share_changed`; read `shareStatus` again).
- Native keeps at most `MAX_SHARED_FILES` (10). `dropped` counts the files beyond the cap
  and the files that are not `content://`.
- A text-only share is reported as `refused/no_files`.
- Android emits the event with `retainUntilConsumed` so a cold start still delivers it.
  `shareStatus` is the pull path. Under the app lock, the event waits until unlock.
- Files are delivered only through the page's own file chooser, after a native confirm
  ("Attach the N shared files here?"). Nothing is uploaded natively.

**iOS (track D):** `WKUIDelegate`
`webView(_:runOpenPanelWith:initiatedByFrame:completionHandler:)` is public on **iOS 18.4+**.
The WebKit header marks it `WK_API_AVAILABLE(macos(10.12), ios(18.4), visionos(2.4))`.
Sources:
[WebKit features in Safari 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)
and the
[Apple reference](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:runopenpanelwith:initiatedbyframe:completionhandler:)).

The app's baseline stays at iOS 17.4, so:

- Implement it behind `if #available(iOS 18.4, *)`.
- On older systems, report `shareReceived {kind:"refused", reason:"unsupported_os"}`,
  delete the copied files, and leave the default picker as it is.

This settles U1. D3(a), which would expose the Documents folder in the Files app, is not
needed. The host has no Xcode, which only limits building and checking here; the API exists.

## 5. URIs (`@yaran/protocol`)

`parseAppUri` and its `AppUri` union are **unchanged**. The two new forms have parsers of
their own, so the shell's exhaustive `deepLinks.ts` switch keeps compiling, and
`controlUrlDecision` ignores both forms. The shell tries `parseAddMachineUri`, then
`parseAgentLink`, then `parseAppUri`.

### add-machine (QR or link; it only pre-fills Confirm machine and never adds)

`yaranapp://add-machine?u=<pct-encoded https://<host>>`, at most 512 characters.

```ts
addMachineUri(host): string          // throws unless isPublicHost(host)
parseAddMachineUri(uri): { ok: true; kind: "add-machine"; host } | { ok: false; code: "uri_invalid" }
```

The form is strict:

- exactly the parameter `u`
- no path, fragment, empty pair, duplicate or other parameter
- `u` is `https://` followed by a public host, with no port, path or userinfo

The scheme is compared case-insensitively.

### Verified agent link (G6, D2b)

```
https://<publisher-domain>/open#o=<pct OrgUrl>&m=<machine Uuid>&a=<agentId>[&t=<tabId>]
https://<publisher-domain>/open#d=<host>&a=<agentId>[&t=<tabId>]
```

```ts
agentLinkUrl(publisherDomain, { target, agentId, tabId? }): string   // throws on any invalid value
parseAgentLink(url, publisherDomain): ({ ok: true } & AgentLink) | { ok: false; code: "uri_invalid" }
type AgentLinkTarget = { kind: "org"; orgUrl; machineId } | { kind: "direct"; host };
```

- **The publisher domain is always passed in. It is never read from the link or the
  machine.**
  - Consumer: the domain of `Session.callbackMode()` when it is `{mode:"https", domain}`. A
    `dev` build passes `""`, and every link is then refused.
  - Producer: the build or runtime config that track A/F hands the machine (D2b:
    `MachineConfig`, derived from `APP_CALLBACK_URLS`). Never a constant in the repo.
- The parser is strict, at most 1024 characters:
  - the scheme is `https`, case-insensitive
  - the authority equals the publisher domain exactly, so a port, userinfo, uppercase or a
    suffix is refused
  - the path is exactly `/open`, with no query
  - the fragment has exactly one target form
  - `m` is a lowercase v4 Uuid
  - `a` is required, and `a` and `t` are `YaranId` (`[\x21-\x7e]{1,128}`)
  - no other, empty or duplicate parameter is allowed
- Ids are carried as ids, not as a nested `#/agent/...` route. The consumer builds the route
  with `agentRoute(agentId, tabId)`.
- **A link opens only a machine that is already known**:
  - `org`: matched by `orgUrl` plus `machineId` against the stored machine list, which
    supplies the host
  - `direct`: matched by the stored direct host

  Anything else gets "That link is for a machine this phone hasn't added." No org or
  machine is ever added from a link (T42).

## 6. G3 research (for track B; no contract change)

- Chromium WebView turns on its `NetworkChangeNotifier` (which drives `navigator.onLine` and
  `online`/`offline`) only when the app holds `ACCESS_NETWORK_STATE`. Source:
  `WebViewChromiumAwInit.doNetworkInitializations`
  (<https://chromium.googlesource.com/chromium/src/+/cc1a78ecc5ed3ad4100344f40755fdebbf4e31b1/android_webview/glue/java/src/com/android/webview/chromium/WebViewChromiumAwInit.java>).
  The minimal fix is the manifest permission, followed by a device check.
- **Do not add the `setNetworkAvailable` fallback pre-emptively.**
  `AwContents.setNetworkAvailable` turns off automatic detection for the whole process, for
  backward compatibility
  (<https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/java/src/org/chromium/android_webview/AwContents.java>).
  Use it only if the device check fails with the permission in place.
